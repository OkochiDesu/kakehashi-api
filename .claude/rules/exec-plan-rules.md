## ディレクトリ構成

- `pending/` - 計画済みだが未着手の実行計画（PR バックログ）
- `active/` - 現在進行中の実行計画（原則1件、一時的に2件を許容）
- `completed/` - 完了した実行計画（アーカイブ）
- `tech-debt-tracker.md` - 既知の技術的負債・後回しにした課題

## ファイル命名規則

`NNNN-内容を表す短い名前.md`（4桁連番）。次に使用できる番号は [docs/exec-plans/README.md](../../docs/exec-plans/README.md) を確認すること。

## 粒度ポリシー（PR 単位）

exec-plan は **原則 1 PR = 1 exec-plan** で作成する。

| 状況 | 対応 |
|---|---|
| 通常の機能 PR | pending/ に1ファイル作成し、PR 着手時に active/ へ移動 |
| 複数の関心事をまとめる PR（一時的） | active/ に2ファイルが存在する状態を許容する |
| 複数 PR にまたがる大きな機能 | pending/ に複数ファイルを用意し、依存関係を記述する |
| 1セッションで完結する小作業 | TodoWrite のみで管理し、exec-plan ファイルは作らない |

Step1 / Step2 など「フェーズをまたぐ PR 群」は別々の exec-plan ファイルに分割する。
1つの exec-plan で複数フェーズを管理しない。

## TODO と exec-plan のすみ分け

| | TODO.md | exec-plan |
|---|---|---|
| 状態 | アイデア・未具体化・検討中 | 完了条件が書ける・主要タスクが3件以上具体化できる |
| 主語 | 「〇〇したい」「〇〇が必要かも」 | 「このPRで〇〇を実装する」 |
| ライフサイクル | 長期保管（腐敗許容） | pending→active→completed で必ず消化 |

**運用ルール**: exec-plan を作成した時点で、対応する TODO.md の項目は削除する（二重管理しない）。逆に設計が未確定で DoD を書けない段階は exec-plan を作成せず TODO.md に留める。

## TODO → exec-plan 昇格基準

以下の3条件をすべて満たせば exec-plan 化する（`pending/` に追加する）:

1. 完了条件（DoD）が書ける
2. 主要タスクが3件以上具体化できる
3. 着手する PR の目的が明確

## フルexec-plan / 軽量プランの判定

タスクに着手する前に、ClaudeCodeは以下を判断し、**判定結果を人間に提案して確認を取る**こと
（このリポジトリでは1機能・1PR単位で人間をヒューマンインザループに組み込む方針のため）。

| 判定 | 基準（例） | 進め方 |
|---|---|---|
| フルexec-plan | 複数PR・複数セッションに渡る作業／後から「なぜそうしたか」を追う必要がある作業 | `pending/` に作成し、着手時に `active/` へ移動する。進捗・意思決定ログを更新しながら進める |
| 軽量プラン | 1PR・1セッションで完結する作業 | TodoWriteのみで管理し、exec-planファイルは作らない |

判定に迷う場合や、軽量プランで開始したが規模が大きくなりそうな場合は、その都度人間に確認する。

## 更新タイミング（ワークフロー）

```
pending/  →（着手時）→  active/  →（PR マージ時）→  completed/
```

1. フルexec-planが必要と判断したら、`pending/` に作成する。
2. 作業の節目（フェーズ完了・重要な意思決定）ごとに「進捗状況」「意思決定ログ」を更新する。`[ ]` 項目に変更が発生した場合は、同一コミットで `[x]` に更新すること（「不要」と判断した項目も後で実施になった場合は必ず反映する）。
3. **完了判定と `completed/` 移動（必須）**: 「進捗状況」セクションの全 `- [ ]` 項目が `- [x]` になった時点で完了とみなす。**次の作業セッションの開始時、または完了を認識したタイミングで速やかに `git mv` で `completed/` へ移動すること**（`rm` 禁止のため `git mv` を使う）。移動と同一コミットで `docs/exec-plans/README.md` の次番号を更新する。
4. 対応を見送った課題は `tech-debt-tracker.md` に追記する。
5. [doc-maintainer-content](../../.claude/agents/doc-maintainer-content.md) サブエージェントが、`active/` 内の計画が現状と矛盾していないか・更新が止まっていないか・全チェックが完了しているのに移動されていないかを定期的にチェックする。

## テンプレート

```markdown
# NNNN: タイトル

## 完了条件（Definition of Done）
このexec-planが完了したとき、以下の状態になっている:
- 〇〇ができる
- 〇〇が整備されている

## 目的・スコープ
何のために、何を対象に行う作業か。

## 進捗状況
- [ ] タスク1
- [ ] タスク2

## 意思決定ログ
- YYYY-MM-DD: 決定内容と理由

## 残課題・引き継ぎ事項
- ...
```
