# ADR Governance スキル

`adr-governance` サブエージェント（[.claude/agents/adr-governance.md](../../agents/adr-governance.md)）を呼び出し、ADRの作成・更新・Supersedeを行う。

## このスキルの位置づけ

**通常は不要**。ADR・AI-ADRの作成・更新が必要な場面では、同一セッション内でメインAIが `adr-governance` サブエージェントを自動的に呼び出す。

このスキルは以下の**救済措置**として使用する:
- セッションが切れてコンテキストを失った場合
- AIが次のステップを見失った場合
- 明示的にADRガバナンスフローを起動し直したい場合

## 使い対象シーン
- アーキテクチャ、CIポリシー、データモデル、セキュリティポリシー、チーム共有のエンジニアリングルールを変更したとき。
- 既存ADRを更新するか新規ADRを追加するかを判断したいとき。
- 低コスト・証拠ベースのADRメンテナンスを行いたいとき。

## 反ハルシネーションポリシー
1. リポジトリの成果物のみ使用する: git diff、既存ADRファイル、トラックされたドキュメント。
2. すべての意思決定はファイル内の証拠を引用する。
3. 証拠がないまたは曖昧な場合は、編集前にユーザーに質問する。
4. 名前だけから未解決の意図を推測しない。

## コスト制御ポリシー
1. Stage 1（安価）: 変更ファイルとdiffサマリーを解析する。
2. Stage 2（絞り込み）: ADR候補と関連ドキュメントのみを読む。
3. Stage 3（オプション）: スコープが不明または最終検証が必要な場合にのみサブエージェント（`adr-search` / `adr-validator`）を呼び出す。
4. サブエージェントの利用は1リクエストにつき各1回まで。

## 手順
1. diffスコープの収集
   - `git diff --name-only <base>...<head>` 等を実行する。
   - 変更種別を分類する: マイナー補足 / ポリシー変更 / アーキテクチャ変更。
2. 関連ADRの検索
   - `docs/adr` で関連するタイトルとセクションキーワードを確認する。
3. 操作の選択
   - マイナー補足 → 既存ADRを更新。
   - ポリシー/意思決定変更 → 新規ADRを作成し必要なら前のADRをSupersede。
   - ADRスコープ外 → 変更なしと報告。
4. 確認を取る
   - 影響を受けるADRと意図する操作を提示する。
   - ユーザーの明示的承認後にのみ適用する。
5. 検証
   - ファイル名ルール
   - ステータスマーカーフォーマット
   - Supersedes/Superseded byの整合性
6. 報告
   - 変更ファイルを列挙
   - なぜ安全な意思決定かを説明
   - 必要な場合のフォローアップアクション

## テンプレートとチェック
- 最終化前に [ADRチェックリスト](./references/adr-checklist.md) を使用する。

## 安全設定
- `git push` は行わない（[CLAUDE.md](../../../CLAUDE.md) 参照）。このスキルは `git commit` も行わず、変更は `git add` によるステージングまでにとどめる（commitの判断は呼び出し元/ユーザーに委ねる）。
