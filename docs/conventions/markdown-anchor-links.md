# Markdown見出しアンカーへのリンク規約

## 背景

`docs/requirements/data-models.md`から`docs/requirements/ui-flows.md`内の`### 補足`見出しへ、GitHubの自動連番アンカー（`#補足`, `#補足-1`, `#補足-2`...）でリンクしていたが、`ui-flows.md`には`### 補足`見出しが各章に1つずつ（計6箇所）存在するため、連番がリンク作成時の意図と1つずつズレており、誤った章を指すリンクになっていた（GitHub Copilotのレビューで検出）。

このズレは見出しの追加・並び替えで簡単に発生し、見た目上はリンクが「切れていない」（アンカー自体は存在する）ため、レビューで見逃しやすい。

## ルール

- 他ファイルへのリンクは、`### 補足`のように同一ファイル内に複数存在し得る一意でない見出しではなく、`## 1. 認証・アカウントコンテキスト`のような**一意なセクション見出し**へリンクする。
- セクション内の特定の補足事項を指したい場合も、セクション見出しへのリンク＋本文中の説明（例: 「1章の補足」）で表現し、`### 補足`そのものへはリンクしない。
- 同一ファイル内に同名見出しを複数置く必要がある場合は、見出し文言に章番号等を含めて一意にすることを検討する（例: `### 1章 補足`）。

## 関連

- 検出: [doc-maintainer-structure](../../.claude/agents/doc-maintainer-structure.md) のチェック項目（リンク整合性）で、`#補足`や`#補足-\d+`のような連番付き重複見出しアンカーへのリンクを検出対象とする。
