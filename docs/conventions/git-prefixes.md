# Git Prefixes

## コミットメッセージ

コミットメッセージは Conventional Commits に従い、以下の形式で記載します。

形式:

```text
<type>: <summary>
```

利用するプレフィックス:

- feat: 機能追加
- fix: バグ修正
- docs: ドキュメント変更
- refactor: 挙動を変えないリファクタリング
- test: テスト追加・修正
- chore: 雑多な保守作業
- ci: CI設定変更

例:

```text
feat: ユーザー登録APIを追加
fix: 認証エラー時に500になる不具合を修正
docs: PRテンプレートの運用ルールを追記
```

## 強制（commit-msgフック）

コミットメッセージの先頭行が `<type>: <summary>` 形式に従っているかを、`.githooks/commit-msg` で自動チェックする。
規約に従っていない場合はcommitが失敗する（merge/revertコミットは対象外）。

- 誤検知やどうしても規約外のメッセージでcommitしたい場合は `git commit --no-verify` でスキップできる
- `core.hooksPath` はdevcontainer経由で自動有効化されている（[Pre-commit Secret Check](pre-commit-secret-check.md)と同じ仕組み）

## レビューコメント

レビューコメントのプレフィックスは、意図と優先度を明確にするためのチーム運用です。
コミットメッセージのような厳密なデファクトスタンダードはないため、広く意味が通じやすい表現を採用します。

利用するプレフィックス:

- must: マージ前に修正が必要な指摘
- suggestion: 改善提案
- ask: 質問、意図確認
- nits: 軽微な指摘
- fyi: 共有のみ、対応不要

例:

```text
must: nullの場合にNPEになるのでガードが必要です
suggestion: この分岐はwhen式にまとめられそうです
ask: ここで404ではなく400を返す想定ですか？
nits: 変数名はitemsよりusersの方が意図が明確です
fyi: Spring Security側でも同様のバリデーションを入れられます
```

## 表記ルール

- プレフィックスの直後には必ずコロンを付ける
- コミットメッセージのプレフィックスは小文字で統一する
- レビューコメントのプレフィックスも小文字を推奨する

レビューコメントのプレフィックスを大文字にする強い一般標準はありません。
must のみ MUST: のように強調する運用もありますが、チーム内で表記が混ざりやすくなるため、このリポジトリでは小文字で統一する運用を推奨します。
