## 背景

`doc-maintainer` サブエージェントによる陳腐化チェックをコミット前に強制する方法として、2つの選択肢を検討した。

1. **pre-commit フック経由で `claude -p` を実行**（機械的強制）
2. **CLAUDE.md の commit運用 セクションに明示**（指示による軟強制）

実装フェーズ（Step1）開始に伴いコミット頻度が増加する見込みがあり、フック方式では以下の問題が生じる。

- コミット毎に `claude -p` が起動するため、トークン消費が増加し課金対象になる
- フックを実行するマシン全台に Claude Code のインストール・認証が必要になる

また、現状の実装者は一人であり、ルール逸脱リスクを人的運用でカバーできる規模である。

## 決定

doc-maintainer チェックは **CLAUDE.md の `commit運用` セクションに必須ルールとして明示** する方式を採用する。

チェック範囲は diff に含まれるファイルに関連する範囲に絞る（`docs/` 全体ではなく、変更ファイルと関連する索引・ADR・設計書）。実装ファイルの変更でも関連する設計書・ADRの陳腐化を確認し、要対応事項がある場合は同一コミットに含めてから進める。

## 代替案

- **pre-commit フックで `claude -p` を実行**: 機械的に強制できるが、コミット毎の課金・全員への Claude Code 導入が必要になる。実装者が一人の現状では過剰なコスト・複雑性を導入するため不採用。

## 影響

- `CLAUDE.md` の `commit運用` セクションに doc-maintainer チェックが必須ルールとして追加される
- `推奨事項` に重複していた旧ルールは削除される
- フックによる強制がないため、ルールの遵守は AI（Claude Code）の動作指針への準拠に依存する

## 今後の見直しポイント

- チームメンバーが増えた場合、または実装フェーズが進んでコミット頻度が落ち着いた場合は、pre-commit フック方式への切り替えを検討する
- その際は本ADRをSupersedeする新ADRで方針を更新する
