## 背景

ユーザーまたは GitHub Copilot の指摘を受けるたびに、メインAIが都度「memory に保存するか / CLAUDE.md に書くか / agent を修正するか」を判断していた。

この判断は CLAUDE.md の「ユーザーから指摘・訂正を受けた場合」のルールに沿って行われていたが、判断プロセスがセッションごとの裁量に委ねられており、同じ間違いの仕組み化が漏れることがあった。再発防止の仕組み化を標準化・省力化するため、この判断プロセス自体をエージェント化する。

## 決定

`.claude/agents/feedback-harness-agent.md` を作成し、指摘受領時の5分類（memory / CLAUDE.md / agent 更新 / AI-ADR / pre-commit）を担当するエージェントとして定義する。

分類フローは以下の通り。

1. grep/正規表現で確実に検出できるパターン → `.githooks/pre-commit` に追加
2. 特定エージェントの設計ミス → `.claude/agents/` を更新
3. プロジェクト固有の行動ルール違反 → `CLAUDE.md` に追記
4. 設計判断レベルの問題 → `adr-governance` に委譲して AI-ADR 作成
5. 一時的な文脈ミス → `memory/` に保存

このエージェントはユーザー確認前に変更を実施しない。分類レポートを提示し、承認を得てから実装する。

## 代替案

- **メインAIが都度判断する（従来の運用を継続）**: CLAUDE.md のルールに沿って毎回メインAIが分類する。却下理由: 判断が属人的（セッション依存）になり、同じ間違いの仕組み化が漏れることがある。エージェント化することで分類基準が明文化され、一貫した対応が可能になる。

## 影響

- CLAUDE.md の「ユーザーから指摘・訂正を受けた場合」のルールが、このエージェントの呼び出し起点として明示的に活用される
- 分類④（設計判断レベルの問題）の場合、`adr-governance` サブエージェントに委譲して AI-ADR を作成する（エージェント間連携が発生する）
- 分類①（grep で検出できるパターン）の場合、`.githooks/pre-commit` への追加が候補となる
- `.claude/agents/feedback-harness-agent.md` を新規追加し、AGENTS.md のサブエージェント一覧への追記が必要になる

## 今後の見直しポイント

- GitHub Copilot の指摘が自動取り込みできるようになった場合（webhook 等）
- 分類の精度が低く誤分類が頻発する場合は分類ルールを追記する
