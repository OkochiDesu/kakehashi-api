## 背景

`docs/adr/README.md` には ADR 索引テーブルに加えて、命名規則・テンプレート・標準構成・ステータス運用・運用フロー・レビュー観点など、大量の運用ルールが含まれていた。

このファイルを AI が読む場合、索引テーブルだけが目的であっても全 200 行超のコンテキストを消費していた。

また、このプロジェクトでは ADR の作成・更新は `adr-governance` エージェント経由で行うことが確立されており、人間が直接 ADR を書くユースケースはない。つまり、命名規則やテンプレートは「人間が参照するドキュメント」ではなく「AI エージェントが実行時に参照するルール」として管理するのが適切である。

ClaudeCode の `.claude/rules/` はグロブパターンでファイルが開かれた際に自動適用されるため、ADR ファイルを開いたとき（`**/*-ADR-*.md`）にルールが自動ロードされる。エージェントが読みに行く必要がなくなる。

## 決定

- 命名規則・テンプレート・標準構成・ステータス運用・ADR対象判断・Supersede ルール・索引更新ルールを `.claude/rules/adr-rules.md`（グロブ: `**/*-ADR-*.md`）に移管する
- `docs/adr/README.md` は「ADR 索引テーブル + ADRエージェント運用への一行リンク」に特化させる
- DOC-ADR-0002 の「フォルダ索引に特化させる」という方針を ADR ディレクトリにも適用する

## 代替案

- **現状維持（docs/ に全ルールを置く）**: 人間向けドキュメントとしては読みやすいが、AI が毎回全コンテキストを読む非効率さが残る。ADR 作成が AI 経由に統一された現在、人間向けドキュメントとしての価値は限定的。却下。
- **docs/ と .claude/ に重複管理**: 二重管理になり陳腐化リスクが高い。却下。

## 影響

- `.claude/rules/adr-rules.md` が ADR 編集・作成時の自動適用ルール集の正となる
- `docs/adr/README.md` は索引のみ（約30行）になり、AI が読む際のコンテキスト消費が大幅に減る
- `adr-governance.md` エージェント定義の命名規則テーブルは `.claude/rules/adr-rules.md` と重複するが、インラインで保持する。理由: glob による自動適用はメイン AI のみに効き、サブエージェントには適用されないため、エージェントがリンク経由で `adr-rules.md` を Read すると全 96 行がコンテキストに追加される。一方インライン保持は該当テーブル（約 10 行）のみで済む。エージェントは ADR 作成時に `adr-rules.md` 全体も参照するためトータルコンテキストは大差ないが、「リンク化するほどのメリットがない」という判断でインラインを維持する
- AGENTS.md の「glob ルール」表に `adr-rules.md` のエントリを追加する

## 今後の見直しポイント

- `adr-governance.md` の命名規則テーブルと `adr-rules.md` が乖離した場合は、`adr-rules.md` を正として `adr-governance.md` を更新する
- AI 以外のツールが ADR を作成・更新するユースケースが生じた場合は、`.claude/rules/` からのルール参照方法を再検討する
