## 背景

`docs/README.md` は `docs/` 配下に入る前の導線（索引）として機能させたい。
従来は「詳細リンク集」方式で、フォルダ横断で個別ファイルへのリンクが多数並んでいた。
これには次の課題があった。

- ADR セクションが `## ADR`（リダイレクト）と `## ADR 作成方法`（エージェント手順）の2箇所に分裂していた
- `## Conventions` / `## Troubleshooting` などが個別ファイルまで列挙しており、各フォルダの README が持つべき詳細索引の責務と重複していた
- 個別ファイルのリストは、ファイル追加のたびに `docs/README.md` への追記が必要になり、追加漏れ・陳腐化が起きやすい
- AI ナビゲーションの観点では、詳細まで列挙すると読み飛ばしが発生し、「どのフォルダに入るべきか」の判断に寄与しない

## 決定

`docs/README.md` を「詳細リンク集」から「フォルダ索引（1行説明付き）」に整理する。

- `## フォルダ索引`: `docs/` 配下の各フォルダを1エントリとし、フォルダへのリンク + 1行説明で構成する。`TODO.md` は docs/ のフォルダ外ファイルとして先頭エントリに置く
- 個別ファイルのリスト・手順説明（ADR Governance 手順・troubleshooting の各項目等）は各フォルダの README に委譲する
- 「フォルダに入る前に必要かどうかを判断できる粒度」を `docs/README.md` の責務とし、それ以上の詳細は各フォルダ README の責務とする

## 代替案

- **A: 現状維持（詳細リンク集）**
  フォルダ横断の個別ファイルリストが増殖しやすく、ファイル追加のたびに追記が必要で、追加漏れ・陳腐化が起きやすい。却下。
- **B: 完全に空にする（リンクなし）**
  索引として機能せず、導線の役割を果たせない。却下。
- **C: フォルダ索引 + 1行説明（採用）**
  追加が「フォルダ単位」の粒度に収束するため陳腐化しにくく、1行説明により AI・人間ともに「入るべきフォルダか」を判断できる。
  AGENTS.md の「表形式でエージェント一覧 + 用途1行」が機能している実績を踏襲する。

## 影響

- `docs/README.md` への追記契機は「フォルダの追加・廃止」時に限定され、ファイル単位の追記が不要になる
- 各フォルダ内のファイル詳細索引は、対応する README（`adr/README.md`・`conventions/`・`troubleshooting/` 等）が正となる
- 新規フォルダを `docs/` に追加した場合は、`docs/README.md` の「フォルダ索引」に1行（リンク + 1行説明）を追加する
- doc-maintainer 系チェックは、フォルダ索引と実在フォルダの整合（追加漏れ・リンク切れ）を確認対象とする

## 意思決定ログ

- **2026-06-26**: 初期案では `## まず見る` セクションに `TODO.md` と `AGENTS.md` を置いていたが、`AGENTS.md` は CLAUDE.md 経由で AI コンテキストに常時ロード済みであり、人間も docs/ を開く時点で存在を知っている。また `docs/README.md → AGENTS.md → docs/README.md` という循環参照が生まれていた。これを解消するため `## まず見る` セクション自体を廃止し、`TODO.md` をフォルダ索引の先頭エントリに移動した。

## 今後の見直しポイント

- フォルダ数が大幅に増え、1行説明だけでは導線として不足する場合（カテゴリ見出しによるグループ化の再検討）
- 個別ファイルへの直接導線を `docs/README.md` から張りたい強い需要が生じた場合（その判断は本ADRの更新または新規ADRで行う）
