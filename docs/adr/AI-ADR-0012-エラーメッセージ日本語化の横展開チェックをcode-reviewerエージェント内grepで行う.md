## 背景

エラーメッセージを日本語化するルール（`require()` / `check()` / `checkNotNull()` / `requireNotNull()` / 各種 Exception のメッセージ文字列を日本語にする）は `.claude/agents/code-reviewer.md` に記載されていた。

しかし PR #10 の Copilot レビューで、エラーメッセージの英語残存が複数ラウンドにわたって指摘され続けた。原因は、ルールは存在したものの **code-reviewer が diff 行だけを目視で確認していたため、同一ファイル内の他のメソッドや別ファイルへの横展開漏れが生じた**ことにある。diff に現れた行は日本語化しても、同種の英語メッセージが diff 外に残り続ける、という漏れが実証された。

横展開漏れを防ぐには、`src/` 全体を対象とした機械的チェックが必要であるが、どのレイヤーでそのチェックを行うかを決める必要があった。

## 決定

`code-reviewer` エージェントの実装品質チェック内に、`src/` 全体を対象とする以下の grep ステップを明示的に組み込む。

```bash
grep -rn 'require(\|check(\|checkNotNull(\|requireNotNull(\|Exception(' src/main/kotlin --include="*.kt" \
  | grep '{ "[A-Za-z]' | grep -v '[^\x00-\x7F]'
```

出力された行を AI が文脈付きで判断し、日本語化されていない英語メッセージを REQUIRES_CHANGES として指摘する。`code-reviewer` は Bash ツールを保持しているため、このチェックをエージェント実行フローの一部として実施できる。

## 代替案

1. **`.githooks/pre-commit` に grep を追加する**: フックは pass/fail のバイナリ判定であり文脈を見た判断ができないため、変数名・enum 値・正規表現の説明文など英字が埋まった正当な日本語メッセージをフォルスポジティブとして検出し、コミットをブロックしてしまうリスクがある。→ 棄却
2. **エージェントの目視確認（現状維持）**: diff 行しか見ない運用では横展開漏れが発生することが PR #10 で実証された。→ 棄却
3. **code-reviewer エージェント内 grep（採用）**: `code-reviewer` は Bash ツールを持ち、grep 結果を AI が判断できるため、フォルスポジティブを文脈で弾きつつ `src/` 全体への横展開漏れを機械的に拾える。検出の網羅性（grep）と判断の柔軟性（AI）を両立する。

## 影響

- `.claude/agents/code-reviewer.md` のエラーメッセージ日本語化チェック項目に grep コマンドを追記する（実装済み）。
- `.githooks/pre-commit` および CI ワークフローには影響しない（フックにはこのチェックを追加しない）。
- grep はあくまで疑い候補を抽出する役割であり、最終判断は AI が文脈を見て行う前提とする。フォルスポジティブを許容した網羅検出という位置づけを維持する。

## 今後の見直しポイント

- grep パターンが拾えない種別のメッセージ（例: 変数経由で組み立てるメッセージ、新たに導入する例外生成 API）が出てきた場合、パターンの拡張を検討する。
- フォルスポジティブが運用上ノイズになりすぎる場合、抽出パターンの精緻化を再検討する。
- 同種の「ルールはあるが横展開漏れが起きる」課題が他のレビュー項目でも顕在化した場合、エージェント内 grep 方式を横展開できるか検討する。
