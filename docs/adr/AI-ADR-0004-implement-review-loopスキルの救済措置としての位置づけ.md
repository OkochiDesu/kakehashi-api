## 背景

Step1実装サポートのワークフロー（[AI-ADR-0001](AI-ADR-0001-Step1実装サポート用マルチエージェントパイプライン構成の採用.md)）では、`kotlin-implementer` → `code-reviewer` のレビューループをメインAIが同一セッション内で自動実行する。

しかし、セッション切れ・コンテキスト喪失・AIが次のステップを見失う等の理由で、メインAIがこのループを自動実行できない場合がある。
その場合の対処手段が必要になった。

## 決定

[`/implement-review-loop`](../../.claude/skills/implement-review-loop/SKILL.md) スキルを「救済措置」として位置づける。

- スキルは `kotlin-implementer` → `code-reviewer` を **APPROVED が出るまで最大3回ループ** する。
- **通常は同一セッション内でメインAIがこのフローを自動実行する**（「実装進めて」の指示で足りる）。
- ユーザーが**明示的に起動した場合のみ**スキルを使用する（セッション切れ・コンテキスト喪失・ループ再起動時の救済）。
- スキル起動の前提条件として、db-designer / api-designer の設計書が作成済みで、人間が設計を承認済みであることを求める。
- 3回ループしてもAPPROVEDにならない場合は、残存指摘事項をまとめてユーザーに報告し判断を委ねる。
- APPROVED後の commit はユーザーの明示的承認後のみ実行する（ヒューマンインザループの維持）。

## 代替案

- **スキルをメインフローとして常用（毎回ユーザーが明示起動）**: レビューループのたびにユーザーが `/implement-review-loop` を手動起動する案。通常の実装依頼でメインAIが自動的にループできるにもかかわらず、毎回手動起動を要求するのは冗長で、ヒューマンインザループの確認ポイント（設計承認・commit確認）以外で不要な操作負荷を増やすため不採用。

## 影響

- レビューループは原則メインAIの自動実行に委ね、スキルは例外時のフォールバックとして残る。
- スキルは `user-invocable: true` であり、ユーザーが明示起動できる。
- 最大3回というループ上限により、無限ループ（REQUIRES_CHANGESの繰り返し）を防止する。

## 今後の見直しポイント

- メインAIが自動ループを安定して実行できず、救済措置スキルの手動起動が常態化する場合は、ワークフローの自動化部分を見直す。
- 最大3回のループ上限が実装の規模・難易度に対して不足/過剰な場合は回数を再調整する。
