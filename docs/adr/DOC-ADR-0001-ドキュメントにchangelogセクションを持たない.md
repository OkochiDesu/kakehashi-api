# DOC-ADR-0001: ドキュメントにchangelogセクションを持たない（git + ADRリンクで代替）

## ステータス

- [ ] Proposed
- [x] Accepted
- [ ] Superseded
- [ ] Rejected

## 日付

2026-06-19

## 関連

- Supersedes: なし
- Superseded by: なし

## 背景

`docs/requirements/` や `docs/design/` 配下のドキュメントが更新された際、「いつ・なぜ変わったか」を時系列で把握したいというニーズがあった。これに対し、ドキュメント末尾に「変更履歴」テーブル（変更日・変更理由・関連ADR）を設ける案を検討した。

一方で、本リポジトリには [doc-maintainer](../../.claude/agents/doc-maintainer.md) サブエージェントによる陳腐化チェックが存在するため、changelog の鮮度を一定程度保つ仕組みは手元にある。changelog を持つべきかどうかを決定する必要があった。

## 決定

ドキュメント（`docs/requirements/` / `docs/design/` 等）に **changelog セクションを持たない。** 代わりに git 履歴 + ドキュメント本文から ADR へのリンクで代替する。

理由:

- **AI 読み込みコスト**: changelog はドキュメントを読むたびに全量ロードされ、「現在の正しい状態」の把握に無関係なノイズになる。
- **維持コストが便益を上回る**: 本文変更時に changelog を更新し忘れると「正確に見える嘘」になる。doc-maintainer で補完できるが運用コストが残り、git 履歴との二重管理にもなる。
- **git + ADR リンクで同等の情報が得られる**: `git log --follow -p <file>` で変更時系列を、ADR リンクで「なぜその記述になっているか」を参照できる。

## 代替案

1. **ドキュメント末尾に changelog セクションを追加する**: 変更日・変更理由・関連ADRを表形式で記録する。
   - 却下理由①: AIエージェントがドキュメントを読むたびに末尾の changelog も全量読むため、「今の正しい状態」とは無関係な過去情報がコンテキストのノイズになる。
   - 却下理由②: 本文変更時に changelog を更新し忘れると「正確に見える嘘」になる（doc-maintainer で補完できるが、運用コストが残る）。
   - 却下理由③: git の変更履歴と二重管理になる。
2. **git 履歴 + ADR リンクで代替する（採用）**: ドキュメント本文の関連箇所に ADR へのリンクを貼ることで「なぜその記述になっているか」を辿れるようにする。時系列の変更履歴は git log で参照する。

## 影響

- `docs/requirements/` / `docs/design/` 配下のドキュメントは changelog セクションを持たない方針とする。
- ドキュメントの重要な記述には ADR へのリンクを添える（例: [data-models.md 0章](../requirements/data-models.md#0-設計方針)の楽観ロック記述 → [ADR-0010](ADR-0010-楽観ロックにversionカラム整数カウンタを採用.md)）。
- doc-maintainer のチェック項目として changelog の有無チェックは追加しない（この方針に従い不要）。

## 今後の見直しポイント

- 監査要件・コンプライアンス要件などで、ドキュメント本文内に時系列の変更履歴を残すことが必須化された場合は、本方針を再検討する。
- git 履歴が rebase・squash 運用で「なぜ」を辿りにくくなり、ADR リンクだけでは追跡が不十分と判明した場合は、changelog 方式を再評価する。
