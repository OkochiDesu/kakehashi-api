# exec-plans 運用ルール

> 出典: [Harness Engineering（OpenAI記事）](../references/harness-engineering/openai-harness-engineering.md) の「計画は第一級の成果物として扱う」という考え方を採用する。

## ディレクトリ構成

- `active/` - 進行中の実行計画
- `completed/` - 完了した実行計画（アーカイブ）
- `tech-debt-tracker.md` - 既知の技術的負債・後回しにした課題

## ファイル命名規則

`NNNN-内容を表す短い名前.md`（4桁連番。[docs/adr/](../adr/README.md) と同じ採番方式）。
次に使用できる番号は **0003**。

## フルexec-plan / 軽量プランの判定

タスクに着手する前に、ClaudeCodeは以下を判断し、**判定結果を人間に提案して確認を取る**こと
（このリポジトリでは1機能・1PR単位で人間をヒューマンインザループに組み込む方針のため）。

| 判定 | 基準（例） | 進め方 |
|---|---|---|
| フルexec-plan | 複数PR・複数セッションに渡る作業／後から「なぜそうしたか」を追う必要がある作業 | `active/` に作成し、進捗・意思決定ログを更新しながら進める |
| 軽量プラン | 1PR・1セッションで完結する作業 | TodoWriteのみで管理し、exec-planファイルは作らない |

判定に迷う場合や、軽量プランで開始したが規模が大きくなりそうな場合は、その都度人間に確認する。

## 更新タイミング（ワークフロー）

1. フルexec-planが必要と判断したら、着手前に `active/` に作成する。
2. 作業の節目（フェーズ完了・重要な意思決定）ごとに「進捗状況」「意思決定ログ」を更新する。
3. 完了したら `completed/` へ移動する。
4. 対応を見送った課題は `tech-debt-tracker.md` に追記する。
5. [doc-maintainer](../../.claude/agents/doc-maintainer.md) サブエージェントが、`active/` 内の計画が現状と矛盾していないか・更新が止まっていないかを定期的にチェックする。

## テンプレート

```markdown
# NNNN: タイトル

## 目的・スコープ
何のために、何を対象に行う作業か。

## 進捗状況
- [ ] タスク1
- [ ] タスク2

## 意思決定ログ
- YYYY-MM-DD: 決定内容と理由

## 残課題・引き継ぎ事項
- ...
```
